# Declarative routes, reference updates, and postprocessing (RimWorld 1.7)

## Route registry

`generation.json` now owns all 132 destinations: 81 animal groups, 29 biome
patches, three venom Def files, and 19 `outputs` entries (plus two
reference-only biome markers without XML destinations) for reproductive
patches, bionics, and life stages. It is the only place where these output
paths are declared. `core/xml_routing.py` validates the destination against
`Zoology/LoadFolders.xml`, validates staged XML and destinations before deployment;
it does **not** guess a destination from an animal name or a folder name.

`outputs[]` entries have a stable `id`, `pipeline_category`, `destination`,
`category`, `requires`, and `source` (`installed_xml` or `generated`). Routes
that update handcrafted XML still require the reviewed corresponding XML in
`Zoology/`. The CE bionics patch is the one new destination: its source mode is
`generated`. Changing `generation.json` alone never deploys anything. Run:

```powershell
py rimworld_patch_generator.py --check
py rimworld_patch_generator.py --all
py rimworld_patch_generator.py --preview
```

Deploy only after inspecting the results in the GUI or with `--deploy --yes`.
Staged XML remains subject to SHA-256 verification. Preview lists all planned
copies, replacements, and unchanged files. Deploy replaces files at declared
destinations even if they differ from an earlier version, without historical
adoption/ownership hashes. Unselected files remain intact. Explicit `prune`
requests still refuse to delete previously generated files changed externally.
Editing a `destination` is not an automatic move; review any old file separately
to avoid retaining duplicate patches in the mod.

## Optimization of all generated Patch XML

The `optimize` checkbox now also postprocesses **biome, product, CE bionics,
and life-stage** patch XML, not just animal group patches. Animal group patches
continue to use their original optimizer without an extra pass. Postprocessing
uses two levels:

1. The OriginalXML-aware optimizer may eliminate a proven redundant operation
   **only when all identified targets in that patch can be resolved in the
   reference index** and the index has no parse/patch errors. Supported target
   kinds include `ThingDef`, `PawnKindDef`, `BiomeDef`, `LifeStageDef`, and
   `HediffDef`. Unrecognized target forms are never treated as proof of a no-op.
2. The existing safe XPath compactor can consolidate compatible operations
   within one Patch file. Its result is accepted only if it reduces the number
   of operations or XPath nodes. Runtime guards remain enabled.

Full `<Defs>` outputs are never passed to a Patch optimizer. With optimization
unchecked the new postprocessing step does not change the generated bytes.
An `optimization-report.json` is written in the staged directory.

**Limitations:** this is not a complete RimWorld patch interpreter, and local
OriginalXML/OriginalPatches may omit mod interactions or different load orders.
The optimizer must not assume that an unknown target is absent at runtime.
The conservative compactor is backed by unit tests but actual game behavior
still needs runtime validation for conditional third-party scenarios.

## Updating reference data

`OriginalXML` and `OriginalPatches` remain **approved snapshots**, not files
silently synchronized on each build. For explicit updates, use the optional
`tools/reference_sync.py` workflow:

1. Copy `reference_sources.example.json` to `reference_sources.local.json`.
2. Fill in real local game/mod directories or GitHub repository URLs. For each
   source, list **explicit** input XML paths and their destination below
   `OriginalXML/` or `OriginalPatches/`.
3. Preview changes (no write):
   `py -m tools.reference_sync --config reference_sources.local.json`
4. Review the changes and then run the same command with `--apply`. Modified
   originals are backed up in gitignored `output/reference-backups/`.

For GitHub sources, configure a **specific full 40-character commit SHA** and
add `--fetch` for either preview or apply. The tool downloads into an isolated
transient directory, verifies the commit, and does not change the checked-out
repository or `Zoology/`. A mutable `main`/`HEAD` is deliberately rejected to
make builds reproducible. Git must be installed for this optional feature.

The updater checks XML roots, source/destination traversal and duplicate maps.
It makes no deletions. Neither a GitHub mod's current branch nor a local game's
installed version is automatically assumed correct for RimWorld 1.7. Updating
an approved reference may change optimized outputs: review XML diffs and run
all validation again after accepting new reference bytes.
