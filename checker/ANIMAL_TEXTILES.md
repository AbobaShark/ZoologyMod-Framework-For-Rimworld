# Wool and animal silk generation

Checker generates wool and silk material overrides from the **Animal textiles**
tab of AnimalStats. This is separate from the **Leathers** tab (leathers and
hides) and **EggMilkWool** (amounts/intervals of animal production).

There is no installer or migration script. The generator is directly integrated
with `core/pipeline.py`, `generation.json`, and the Checker GUI/CLI.

## Source data

The `Animal textiles` tab contains one row per material `ThingDef`:
`Name`, `Type` (Wool/Silk), `Source mod`, `MarketValue`, `Beauty`,
`MaxHitPoints factor`, `StuffPower_Armor_Sharp`,
`StuffPower_Armor_Blunt`, `StuffPower_Armor_Heat`,
`StuffPower_Insulation_Cold`, `StuffPower_Insulation_Heat`,
`Flammability factor`, `Color hex`, `CE Armor Sharp`,
`CE Armor Blunt`, `CE Armor Heat`. The provenance column is documentary,
not an input to the material generation algorithm.

The supported original groups are Core, Odyssey, AlphaAnimals, Megafauna and
Vanilla Animals Expanded. Only those groups receive a generated XML route.
Missing source definitions are errors, not invitations to create new materials.

## Refresh and generate

Use `reference_sync_gui.py` to preview and apply upstream reference XML for
the installed game, DLCs, optional mods and Combat Extended. Both leather and
textile material XML go into the existing source-relative `_Leathers`
reference directories. These are input snapshots and are not loaded by RimWorld.

From the `checker` directory:

```powershell
py rimworld_patch_generator.py --category textiles --source "D:\Data\AnimalStats.xlsx"
py rimworld_patch_generator.py --preview
py rimworld_patch_generator.py --deploy --yes
```

You may generate leathers at the same time with a second `--category leathers`.
For an individual tab, use `--sheet "Animal textiles=D:\Data\Animal textiles.tsv"`.
To generate without CE snapshots, explicitly pass `--no-ce` (this means
that no CE-specific material override will be generated).

Generation compares the sheet to original material definitions, following
`WoolBase` and `ResourceBase` inheritance, and applies CE reference patches
against a simulated Def database. It emits only differing values. CE overrides
are grouped at the end of the source-specific output, under a Combat Extended
mod-presence condition. Original files must be synchronized before generation;
unknown stat comparisons and missing materials fail rather than silently
producing a partial material rebalancing.

The old handwritten `WoolCamel` insulation edits were removed from the VAE
leather patch. They are generated by the textile route instead; a source sync
is therefore necessary before deploying the textile category.

## Upstream conditional materials

Some upstream material definitions are loaded only when another mod is absent.
For example, Vanilla Animals Expanded loads
`1.6NotOdyssey/Defs/ThingDefs_Items/Items_Resource_WoolLeather_NO.xml`
only without Odyssey (including RimWorld 1.7). Its `AEXP_MuskOxWool`
must therefore not receive an unconditional Zoology override just because VAE
itself is installed.

Checker derives this condition from the synchronized original source path.
Any wool/silk material from a recognized `NoOdyssey` or
`1.6NotOdyssey` source receives a `PatchOperationFindMod` with an Odyssey
`nomatch` branch. Both normal and Combat Extended operations stay inside the
branch, and CE baselines are simulated with Odyssey absent for that material.
Materials from unconditional sources (such as `WoolCamel`) are unaffected.
Reference Sync must retain the upstream-relative source path.

## Leather routing and empty-output handling

The **Leathers** tab requires an explicit `Source mod` column (the live
AnimalStats workbook has this in column M). Each material must declare its
actual owner: `Core`, `Odyssey`, `AlphaAnimals`, `Dinosauria`, `Megafauna`,
`Vanilla Animals Expanded`, `Vanilla Animals Expanded — Endangered`,
`Vanilla Animals Expanded — Waste Animals`, `Zoology` (the four standalone
Zoology leathers), or `External` (other projects not patched by Zoology).

This is checked against the owning upstream ThingDef in `OriginalXML`.
For example, `Leather_AlphaThrumbo` belongs to **Odyssey**, not Alpha
Animals, even though the animal name contains "Alpha". The reference
directory and the `Source mod` value must agree. If generation fails on
outdated local values, download the latest AnimalStats workbook rather than
changing a verified source ownership to hide a missing reference.
A missing or mismatched original fails generation, rather than routing
a skin to an unrelated mod or silently skipping it. Source-specific output
is placed only in `generation.json`-registered paths; both Vanilla material
properties and CE material overrides share that same source-specific output.
CE operations execute after Vanilla operations under a Combat Extended
presence test.

Only actual differences are emitted. In addition to generated differences,
the historical Core leather-stat operations are trimmed when their values
equal the original. CE reassertions are retained when a preceding Vanilla
override requires them. Empty generated material outputs are not deployed:
their registered destinations appear as explicit DELETE operations in the
staged deployment preview, with checksum checks for previously deployed files.
Handcrafted and conditional fallback XML are never deleted by this cleanup.

If you have an older local `.xlsx` without `Source mod`, download a fresh
copy of the live AnimalStats spreadsheet before using `--category leathers`.
The source workbook and the installed mod tree must be synchronized separately;
`--preview` only reviews staged XML and does not write it.
